# Website sources

The website at https://semts-ontology.github.io/SemTS/ is one static page, `index.html` in the repository root, generated by `tools/build.py` from these files and from the Turtle sources. Do not edit `index.html` or `data/` by hand.

| File | Content |
|---|---|
| `src/body.html` | The markup of all pages. Each page is a `<section class="page" data-page="…">` |
| `src/app.js` | Routing, page renderers, examples metadata, applications, snippets |
| `src/arch.js` | Nodes and edges of the architecture diagram on the Ontology page |
| `src/pics.js` | The SVG pictures of the home page and the examples |
| `src/styles.css` | Styles |
| `vendor/webvowl/` | WebVOWL, copied with generated data to `ontology/versioned/<version>/webvowl/` |

The Turtle examples are read from `../examples/`, the ontology, shapes and vocabularies from their folders. Run `python3 tools/build.py` after any change and commit the generated files. The CI workflow fails if they are out of date. Preview locally with `python3 -m http.server` in the repository root.

## Adding a page

Pages are registered in `ROUTES` at the top of `src/app.js`. An entry creates the navigation item, the address and, for documentation pages, the entry in the side navigation:

```js
const ROUTES = [
  // ...
  { id: 'tutorial', title: 'Tutorial', nav: 'Tutorial' },          // top navigation item, address #tutorial
  { id: 'tools', title: 'Tools', docs: 'Using SemTS' },             // listed in the documentation side navigation
];
```

Then add the page frame to `src/body.html`:

```html
<section class="page" data-page="tutorial" aria-label="Tutorial">
  <div class="wrap">
    <div class="page-head"><h1>Tutorial</h1><p class="lede">…</p></div>
    …
  </div>
</section>
```

If the page needs data from the graphs, add a renderer to `INIT` (or to `NEEDS_VOCAB` if it needs the vocabularies) in `src/app.js`. Terms written as `<ul class="termlist" data-terms="semts:TimeSeriesSegment …">` are linked to the diagram and the specification automatically.

## Releasing a version

1. Update `ontology/current/ontology.ttl` (`owl:versionInfo`, `owl:versionIRI`, `owl:priorVersion`, `dcterms:modified`) and the shapes header.
2. Run `python3 tools/build.py --snapshot`. This writes `ontology/versioned/<version>/` with the serialisations, the shapes, the WebVOWL graph and a frozen copy of the website, which is what the versioned w3id IRI resolves to.
3. If `src/arch.js` changed, export the diagram with "Copy diagram as SVG" on the Ontology page and save it as `assets/images/semts_architecture_<version>.svg` (with `width` and `height` set to the view box), then run the snapshot again so that the versioned copy is updated. The README shows a PNG of the same diagram (`assets/images/semts_architecture_<version>.png`, rendered at twice the size on a white background) and a screenshot of the home page (`assets/images/semts_website.png`). Update both when the diagram or the home page changes.
4. Update the "Changes" page in `src/body.html`, `CHANGELOG.md`, and the w3id rules if new modules were added.
